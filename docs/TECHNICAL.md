# Tether 技术说明

## 现有链路

完整原生页面链路为：DeepSeek Harness 桌面 Tether 面板 → 每设备回环 gateway → Controller / Node WebSocket → 目标正在运行的 DSH Desktop Web Host。Host companion 只发布现有 Host 的本机连接描述，不另启 SDK 或创建第二个会话写者。模型、权限、文件引用、附件和轨迹使用目标提供的原生前端及接口。

文件资源管理器是插件唯一的文件管理页（原生工作区入口之外）；互联页列出全部节点并在右侧画本机居中拓扑。旧日志读取器和 SDK 任务接口保留为后端兼容/证据，但不再作为插件入口。DESKTOP-LOCAL 已实机验收，LAPTOP-01 旧节点尚缺新协议与 companion，需要更新后才能验收双机功能。细节见 `native-surface.md`。

审计使用目标机 Node 的 SQLite（`audit.db`，WAL）保存最近 100000 行，API 支持 `limit/offset` 分页；旧 `audit.jsonl` 首次启动时迁移为 `.migrated`，内存不随历史增长。文件页、权限页、互联页都在 DSH client 插件内；设备切换在顶栏，互联页负责全局视图。设备显示名存 Controller 的 `devices.display_name`，`device_id` 和 `host_name` 不变；节点重连不会覆盖别名，客户端从 `/api/state` 同步。

## 本轮修改约束

- 以 DeepSeek Harness MIT 原生 UI 组件为呈现基准，版本与源文件哈希写入复用说明。
- 不修改上游安装包内部代码；适配层留在 Tether 包中。
- 工作区的显示名称、实际路径与文件夹 basename 是不同字段，不能互相替代。
- 文件树的展示身份与物理路径缓存分离；展示身份含设备与分组，缓存按设备和规范路径隔离。
- 异步响应必须校验设备/请求归属；过期响应不能改写当前页面。
- 目录列表按完整路径去重，递归渲染拒绝祖先循环；加载、空目录和失败状态分别展示。
- 同一会话的展示选择与消息发送目标必须一致；不能隐式选择工作区里的另一个历史会话。

## 验证边界

代码语法检查、离线回归、真实 Controller 读取、浏览器渲染和桌面插件验收分别记录。离线 fixture 不等于跨机或模型调用验证。本轮 UI 验证默认不触发模型调用。

## 编码四原则

1. 编码前思考：先定位现有代码和实际行为，明确假设与权衡，再确定修改范围。
2. 简洁优先：优先复用原生组件，用满足当前需求的最少结构实现；不为猜测扩展接口。
3. 精准修改：只改反馈涉及的代码，保留有效数据、配色和交互，清理本次产生的孤儿代码。
4. 目标驱动执行：把目录不重复、选择不串线写成判据，回归通过后做真实渲染验收。
