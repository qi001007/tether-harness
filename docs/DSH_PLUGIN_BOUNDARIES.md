# DSH / 插件边界

2026-11-03 主人明确口径：**Tether 只管自己的注入，DSH 和其他插件由用户自己管。**

## 接触点（只做这三件）

1. **启动 DSH**：APP 已打开但 DSH 没运行时，一键启动。
2. **安装原版 DSH**：机器上没有 DSH 时，按官方源安装原版。
3. **注入 Tether 插件**：
   - 自动安装 DSH 时顺带注入；
   - 用户已有原版 DSH 时，按需注入。

除此之外不揽事。

## 明确不做

- **不在 DSH 每次更新后自动重装 Tether 插件**。0.2.90 的“版本变化自动重装”已 revert，不发布。
- **不管理、不更新、不修复第三方插件**。用户装了哪些插件、它们是否兼容 DSH 更新，不在 Tether 责任范围。
- 第三方插件在 DSH 更新后坏掉，只记录为第三方问题，不替它修。
- 不因为第三方插件冲突去改 DSH 全局依赖或全局配置。

## 自己的恢复边界

- 只有 **Tether 自己的 surface 缺失/损坏** 时才自动修复；只触碰 4 个 Tether 包及其声明的依赖。
- 不动其他插件的文件、版本和配置。
- 修不好时显示明确状态，不暴露裸控件，不让用户拷文件。

## 映射保真

- 映射页必须是**带当前全部插件的真实 DSH 页面**，不是原版 DSH 快照、不是 Tether 重画版。
- 用户在 DSH 里装的插件、改的页面、注册的命令/面板，映射后必须仍然存在并可操作。
- 如果 Tether 面板/桥接导致其他插件不显示或不可用，算 Tether bug；这是后续第三方插件实测的重点。

## 测试计划

- 等主人选定 1–3 个插件后，在隔离 profile/VM 做安装/卸载/更新/损坏矩阵。
- 每个插件都要验证：DSH 原页面可用、Tether 映射页面与 DSH 一致、Tether 自身注入不影响该插件。
- 不以“Tether 自己能开”代替“带插件的 DSH 能正常用”。

## 当前状态

- 0.2.89 已能自动启动/安装 DSH、注入 Tether 插件、在自身 surface 缺失时修复。
- 0.2.90 的 DSH 版本变化自动重装已 revert，不发布。
- 第三方插件实测待主人选型；DSH 当前基线 rc.5。
