# Tether 产品需求

## 本轮目标（2026-10-27）

用户连接目标设备后，看到目标电脑的 DeepSeek Harness 工作区、会话与原生对话体验，并在旁边使用资源管理器访问目标文件。优先直接复用 DeepSeek Harness 的原生组件和样式，保留开源来源与许可证。

## 核心产品方向与当前未完成项

APP 与 DSH 插件是平等、可独立下载和运行的客户端，各自能安装、启动和管理自己的 Tether 后端；它们不应形成“APP 主体、插件只是 APP 附属入口”的依赖关系。目标节点也应有独立可管理的 Node 后端。独立后端不代表重复创建 DSH 会话写者：同一物理节点上的 APP 与插件必须连接到同一个 DSH Host 和同一个会话真源，Hub 负责路由状态和事件，不调用模型或另开会话。

同节点的 APP、插件及远端节点需实时看到同一任务/命令/对话状态。每个实际运行的后端实例需有唯一 `backendInstanceID`，并与稳定 `nodeID`/设备身份区分；同一 `device_id` 的并存、重连或切换时必须有明确唯一所有权，避免两个本地后台抢占节点身份或产生双写者。克隆完整仓库后应可按文档分别安装 APP、插件和 Node；克隆源码可作为开发路径，不能冒充独立产品安装包。

APP、插件和目标 Node 都必须展示版本/兼容状态，并提供一键更新，不要求用户手动 `git pull`。更新前需校验统一版本清单中的组件版本、协议版本和最低兼容版本；下载制品要走可信 HTTPS 并校验完整性/签名；先暂存，任务运行时不得自动重启；保留账户凭证、密钥、会话及工作区数据；失败可恢复到上一版本。客户端更新不得上传节点密钥。

上述能力当前均作为待实现/待验收需求跟踪，具体门禁见 [`CORE_RECOVERY_PLAN.md`](CORE_RECOVERY_PLAN.md)。README 中现有源码启动、Hub 连接或版本提示不代表已经满足独立制品与一键更新要求。

## 仓库与发行边界

- 项目清理保留有价值的工程文档和用户历史记录；不重写既有历史决定。清理只调整当前公开工作树中的过时服务端实现、临时过程资料和旧发行包，并将需要保留的材料按清单归档。
- 用户决定保留公开仓库。服务端实现独立保存在私有仓库；公开仓库保留当前客户端源码与产品文档，不暴露私有仓库地址或部署资料。
- 服务端独立私有仓库已创建并完成源码上传；公开主分支的旧服务端源码已删除并完成全树检查。用户决定继续保持客户端仓库公开、保留有效历史，不重写先前决定。
- 旧 `v0.2.0` Release 的两个 ZIP 资产已移除，Release 说明标记为 withdrawn，tag 保留。`v0.2.1` 的 APP、插件和 Node 独立 ZIP 及更新清单已公开发布；真实目标环境安装、后续更新、远端 Node 更新和回滚仍按 F30 跟踪。

## 验收标准

- 工作区侧栏显示目标设备的工作区标题与会话；设备切换后不串数据。
- 对话展示使用 DeepSeek Harness 原生 Markdown、思考、工具和运行状态组件；不把只读历史显示成可以原地继续的可写会话。
- 完整原生页面是唯一对话展示，必须接入目标正在运行的 Host，包含模型选择、会话权限、附件、目标工作区文件引用及轨迹；不再提供 Tether 自写日志预览入口。
- 原生会话附件入口必须能从当前 DSH Host 所在的目标设备读取用户选择的文件，并将字节交回原生 composer 附件流程；文件读取遵循 Node 文件策略、单文件上限和目标/会话切换保护。
- 过程区保留“轮次 → 已调用工具分组 → 单条思考/工具详情”的独立收起层级。工具行使用原生图标与简明摘要，展开后可查看输入和输出，顺序与实际调用一致。
- 资源管理器保留“工作区”和“此电脑”两部分。
- 工作区文件树为“用户自定义工作区名 → 实际目录名 → 目录内容”；工作区标题和真实目录名分别保存。
- 重复展开、收起、刷新不产生重复目录或文件；同名不同路径、同路径不同分组和不同设备彼此独立。
- 保留已有文件读写、目录操作、设备切换、权限和审计入口。
- 同一节点上 APP 与插件均能独立运行其后台，同时连接同一个 DSH Host/会话；双向事件、任务和命令状态实时同步，只有一个会话写者。
- APP、插件、目标 Node 均提供版本/协议兼容提示与一键更新，安全更新失败可回滚，且不覆盖凭证、密钥、会话和工作区数据。
- 完整仓库克隆后，按文档可分别启动/安装各组件；仓库克隆步骤与面向用户的独立产品下载分开验收。

## 跨项目视觉准则

背景色建立层次；避免黑框。暗色模式降低字重。回复以克制的水墨晕开效果出现，轮询不能重复播放。变化中的数字等宽。拖拽即时跟手，复位可有短暂回弹。遵循系统的减少动画偏好。

侧栏沿用现有配色和交互，统一字号、圆角与间距；同级面板圆角一致，左右留白一致；图标略小于文字且图文间距固定；行高容纳文字和上下留白；点击区域足够大；组间距大于组内距。
