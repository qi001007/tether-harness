## 3. 已知故障与边界（按优先级）

### 3.1 P0：节点↔Hub WebSocket 的 keepalive 掉线爆发

**证据**（`apps/tether-app/data/logs/node.log`）：

```
[14:33:52] [ws] registered as DESKTOP-LOCAL at wss://8-220-198-26.sslip.io/ws/node
[14:34:32] [ws] disconnected: ConnectionClosedError: sent 1011 ... keepalive ping timeout
[14:35:34] [ws] registered ...
[14:36:14] [ws] disconnected: ... received 1011 (internal error) keepalive ping timeout
[14:37:21] [ws] registered ...
[14:38:21] [ws] disconnected: ... 
[14:38:27] [ws] registered ...（之后到采样时保持稳定）
```

2026-10-29 14:34–14:38 约 4 分钟内出现 20 次 `keepalive ping timeout`，期间更新检查报 `[update] check ... failed: InvalidStateError`；14:38:27 之后恢复，最近采样（14:41）两台设备均在线。也就是说它**不是持续掉线，而是在 APP/Node 重启或网络切换的过渡窗口成串爆发**，需要复现定位，不能因为现在稳定就当已修。客户端参数 `tether/node/agent.py:406`：`ping_interval=20, ping_timeout=20`；服务端 `uvicorn.run(...)`（`app.py` 约 1003 行）没有显式 `ws_ping_interval/ws_ping_timeout`，用 uvicorn 默认 20/20；链路经 Caddy。

**影响**：设备 online 状态抖动、远端更新/检查偶发失败、`InvalidStateError`（对正在关闭的 WS 发送消息，`websockets` 抛该异常）；审计里注册记录被刷。

**建议排查顺序**：

1. 在实验台用一个最小 `websockets` 客户端连 Hub，打印 ping/pong 与关闭码，确认是客户端收不到 pong、服务端收不到 pong，还是 Caddy 侧断开。
2. 看 Hub 事件循环是否被同步操作卡住 20 s 以上（SQLite 调用、mirror 刷新、`_dispatch_queued`、surface mux）；可给 `/ws/node` 加 pong 时间戳日志。
3. 给 uvicorn 显式设置 `ws_ping_interval/ws_ping_timeout`，并确认 Caddy 没有对 WS 设空闲超时（当前 `deploy/hub/Caddyfile.example` 无显式 WS 超时）。
4. 客户端在 `_send`/更新检查处捕获 `InvalidStateError`/`ConnectionClosed`，重连后退避并重放；不要吞掉用户可感知的失败。

**不要**把这件事当成“重复 node 进程”处理：当前两个 Python 进程是 venv stub + Anaconda 解释器，只有一个持有 18894 和 Hub 连接。

### 3.2 P1：更新中心 `latest` 的刷新时差

- Hub mirror 的 GitHub `latest` 解析缓存 `latest_ttl=300s`（`releases.py` 的 `ReleaseMirror`）；manifest 本身 `ttl=60s`。
- 客户端 `tether/updates.py` 还有内存 60 s / 磁盘 600 s 的清单缓存；UI 还有每组件的检查缓存。
- 实测：0.2.24 于 `06:23:28Z` 发布，Hub 在 `06:26:39Z`（约 3 分钟）才返回 0.2.24；期间本机节点卡显示 `0.2.24(0.2.23)`，远端的插件行也可能停在旧 latest。
- **契约**：每个设备的 `latest` 必须取清单值（缺失才回落 current）；**不允许**把 current 冒充 latest（0.2.24 已删除这个显示夹紧）。发布后“刷新立刻变新”需要服务端把 `latest_ttl` 降到 30–60 s，或在版本不一致时强制重解析；这属于服务端改动，需主人授权。
- 诊断：`GET https://8-220-198-26.sslip.io/releases/manifest` 看 `X-Tether-Manifest-Version`；`apps/tether-app/data/updates*/**/latest-*.json` 看各组件的 `checked_at`/`source`。

### 3.3 插件端本机面板不内嵌 DSH（设计边界，别改回去）

桌面 DSH 窗口顶层是 `dsh-app://app`。DSH 的会话 Cookie 是 `SameSite=Strict`，对 `127.0.0.1` 子 frame 不发送 → 401；`dsh-app` 同源子 frame 没有 preload → 停在 `Loading plugins…`；公网 Hub ticket 在本地实例上与宿主客户端争用/超时。三种 iframe 路径都验证过（CDP 真机）。

现状：本机设备显示“当前已在 DeepSeek Harness 中；本机工作区无需再嵌入”，**远端设备仍通过 Hub surface 渲染**（2026-10-29 用 LAPTOP-01 的公网 surface 在 headless 浏览器验证：页面启动、侧栏无 Tether 插件、不递归）。插件入口的 `window.top !== window.self` 守卫必须保留。

### 3.4 P2：节点/APP 的 `restart_required` 残留

`applied-<component>.json` 对 node/app 会保留 `restart_required=true`；UI 用“运行版本 == 目标版本”判定完成，不阻塞链路。若要清理，可在新进程启动后按 `applied_at` 与进程启动时间比较（`psutil.Process().create_time()`）自动清除。插件组件已在 0.2.24 处理（Host pid 变化或 apply 后新 Host 发布 descriptor）。

### 3.5 已知环境陷阱

- `ELECTRON_RUN_AS_NODE=1` 会让 DSH/APP 以纯 Node 启动、窗口不起来。启动前必须清除；`dsh_restart.py` 已在 0.2.24 剥离该变量。
- `.venv` 的 base 是 Anaconda；`pip install`/依赖版本以 venv 为准，不要在 Anaconda base 里装。
- 中文路径 + GBK 控制台：PowerShell/命令行传中文路径会乱码；脚本内用对象/UTF-8 文件传参。
- 本机 DSH desktop profile 的 `tether-dsh-plugin` 是 `file:E:/遥望科技实习项目/tether/packages/dsh-plugin-tether` 拷贝安装；改了 bundle 必须 `desktop/install-plugin.ps1` 重新 add，再重启 DSH。

## 4. 更新系统契约（别破坏）

- 组件：`app` / `plugin` / `node`；协议常量 `1`；`min_updater=0.2.1`。
- 清单：`schema=1`、`channel`、每个组件 `version/url/size/sha256/protocol/min_protocol/min_updater/rollout`，Ed25519 签名（`tether/release.py` 验签；仅 loopback 开发源可无签名）。
- 流程：`check`（强制）→ `prepare`（下载、验签/哈希、解包、暂存）→ `apply`（备份、原子替换、写 `installed/applied`、更新 `version.json`）→ 重启（node 退出 75 由 supervisor 重启；插件触发 DSH helper；APP 由 helper 退出后替换并重启）。
- 状态：`data/updates/<component>/`（`latest-*.json`、`manifest-cache.json`、`installed-*.json`、`applied-*.json`、`prepared/`、`backups/`）。
- 远端一键更新链：node → plugin → app；单个组件失败不阻断后续（0.2.18 起）；对 `device_offline`/重启间隙有重试。
- 发布：PR 合 main → `workflow_dispatch` `release.yml`（输入 `tag=vX.Y.Z`）→ 草案 → 人工核对签名/大小/SHA → 发布 → Hub mirror 刷新。

## 6. 红线

1. 不许把本机插件面板改回内嵌 DSH（§3.3）；不许删插件入口的 embedded 守卫。
2. 不许用 current 冒充 latest；本地与远端必须显示同一份清单 latest。
3. 后台自动检查失败只留卡片状态，不弹红 toast、不点红点；显式操作才报错。
4. 不改服务端/部署/secret，不推 tag、不改 CI，除非主人明确授权。
5. 写类操作一次一个；改文件用锚点式编辑；不要覆盖工作树里主人的改动；git 操作前先 `git status`。
6. 一个事实只有一个主人：更新契约看 `docs/RELEASES.md`/`docs/TECHNICAL.md`，进度看 `docs/PROGRESS.md`，目录约束看各目录 `backlog.md`；不要复制多份。
