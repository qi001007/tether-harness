# 限时 SFTP 转发

## 设备内置同意

在中继设备的 Tether 个人设备网打开自动转发。设备记住当前所有者的选择。发送单个文件时，Hub 核对当前账户、同一私网和在线设备，再为本次传输签发短期许可。接收和转发 Node 各自在本机保存私钥，接收端按 Hub 下发的证书验证转发端。

支持共享端口的双方使用私网 SFTP 入口 20222。现有 SSH 文件连接仍由 SFTPGo 处理，获准的双向 TLS 连接由转发器处理，无需为一次转发重启组网进程。接收器仍核对源端 SSH 公钥和整件文件摘要。双方未协商共享端口时可沿用旧版专用端口 20223。任务结束、许可到期或所有者关闭转发后释放相应授权。

还可用以下独立运维入口进行受控诊断。

## 独立运维入口

中继设备所有者可以手工启动 `python -m tether.node.sftp_relay`。模块随 Node 源码交付，普通启动流程保持关闭。运行时必须提供 `--owner-opt-in` 和未来时间戳 `--expires-unix`，到期后关闭监听器和会话。执行 `--help` 可查看参数。

- `--listen-ip` 指定已核对身份的本机私有组网接口地址，`--listen-port` 指定空闲端口。接收端地址由 `--client-ip` 指定。请在启动前用现有受管控制面核对两设备属于已批准的同一私网。
- 在接收端设备本机生成私钥和 CSR。通过已有受认证通道交换 CSR、客户端证书和 CA 证书。服务端证书的 SAN 应包含私有监听地址。使用独立短期 CA，客户端和服务端须验证对方，服务额外固定获准客户端证书 DER 数据的 SHA-256。私钥保存在所有者独占目录。
- `--upstream-port` 只接受本机 IPv4 回环端口。操作方预先建立可信的上游通道，例如在启用 `StrictHostKeyChecking` 和 `ExitOnForwardFailure` 的现有 SSH 连接内，把原云 SFTP 端口映射到此回环端口。中继保持 SFTP 密文，接收器沿用独立获得的原源端 SSH 主机公钥、任务密钥和文件校验。

直接绑定私有接口的运维试验不会在 Node 公布能力。例如 Tailscale 上的监听地址与 Hub 使用的 EasyTier 服务地址不同。

手工运维可选用 Node 数据目录记录短期监听状态，用于受控调试。此模式要求已有 EasyTier 工作端口映射（52000–52063），并预先配置 CA 和客户端证书。普通任务使用上面的内置自动选路。
