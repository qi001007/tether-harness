# Tether UI 源码变更记录
- 2026-10-28：同一设备工作区重试失败时保留上次有效列表和选择；设备切换时清理旧目标工作区，legacy fallback 仅在目标尚无工作区数据时建立。
- 2026-10-28：工作区响应验证 `workspaces` 列表；异常在工具栏提供局部提示与重试，不再导致 React 白屏。Web 启动入口增加渲染错误边界和重试入口。
- 2026-10-27：移除已废弃的 APP 专属 `app-services.js` 占位组件；APP 连接入口只由共享 `app.js` 挂载。
- 2026-10-27：APP 与 DSH 共用同一“连接”入口及服务器连接面板；展示实际 API base 的地址、连接状态、最近检测与耗时，并支持重新检测。DSH 显式 Hub 时按 Hub 探测；业务 API 回退到 APP 代理后显示 APP 实际服务目标。Hub 编辑移入现有设置抽屉，不进入共享面板。
- 2026-10-27：共享 DSH 面板删除本机/目标节点及设备计数重复项，显示脱敏 Hub 地址和 `/api/state` 客户端请求耗时；失败后清空旧成功结果，URL userinfo/query/hash 禁止保存。
- 2026-10-27：DSH 状态 probe 区分 HTTP 401/403 的凭据/权限错误与不可达/超时；服务响应耗时 title 明确为客户端到服务接口的请求时间。
- 2026-10-27：无 Hub 配置时地址编辑框保持空值并显示 placeholder，摘要显示“未配置”、断开按钮禁用；旧配置含 userinfo/query/hash 时不显示秘密内容、不静默改写，提示用户重新输入安全地址。

- 2026-10-27：本机身份每 4 秒同步，状态失效时清除；非手动选择时自动切换到本机 Node，手动选中节点保持不变。

- 2026-10-27：APP、DSH 本机插件及当前在线选中节点每 6 小时检查一次更新；标题栏显示新版本或检查失败提醒，检查按组件、设备与选择 epoch 隔离并合并并发请求，不触发安装。

- 2026-10-27：修正一键更新阶段失败处理；各宿主返回 ok:false 会进入错误态，序列失败立即停止，authority 始终取自本次检查结果并原样传递。

- 2026-10-27：更新中心加入单组件一键更新，串行执行检查、下载校验、安装；设备目标变更时中止后续步骤，目标设备安装继续固定检查得到的 authority，并保留原有独立操作入口。

- 2026-10-27：API 请求在每个候选 base 上单独获取宿主请求头，避免 Hub 凭据随本机回退请求发送。
- 2026-10-27：移除旧版 `version.json`/`git pull` 提示，改为可手动打开的更新中心；APP 自更新走受信任 IPC，Node/插件更新只对明确选中的设备调用 Controller API，并显示目标身份、版本、离线/旧协议/忙碌状态和重试入口。
- 2026-10-27：DSH 更新中心新增当前插件本机卡片，通过插件实例 RPC 更新自身；另保留明确标注的选中目标设备插件卡片，二者互不混淆。
- 2026-10-27：目标设备更新状态按 deviceId 与选择 epoch 隔离；切换设备清除旧准备包与错误，迟到响应不能覆盖当前设备状态。
- 2026-10-27：目标设备更新在状态/检查时固定当前 API authority，prepare/apply复用同一Hub或Controller地址；更新请求失败不会跨控制面回退。
